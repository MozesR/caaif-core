# Project governance — candidate

CAAIF starts as a maintainer-led research project. Maintainer identities, decision authority, and ownership are **to be confirmed before publication**.

- **Core changes**: require public design rationale, API compatibility discussion, and tests.
- **Security changes**: privately coordinate advisories; no premature public exploit disclosure.
- **Protocol changes**: versioned specification and conformance examples, clear deprecation periods.
- **Third-party adapters**: optional packages; independent maintainers can own adapters with review.
- **Licensing**: no unilateral changes; require rights-holder approval and contributor notice.
- **Releases**: release manager signs the checklist and publishes changelog and checksums. 'CI passed' is not release authorization.

Initially one or a small number of named maintainers may approve changes; publish the actual maintainers and escalation procedures before accepting outside contributors.
